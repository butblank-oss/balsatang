# 발사탕 운영 가이드

화면이 셋이다. 이름이 헷갈리기 쉬워 먼저 정리한다.

| 화면 | 주소 | 무엇을 하는 곳 |
|---|---|---|
| **어드민** | `/balsatang/admin/` | 성분 사전 · 콘텐츠 · 태그 · 리콜. 원래 있던 화면 |
| **사료 관리** | `/balsatang/admin/foods.html` | 발행된 사료를 고치고 **GitHub 에 바로 커밋**. 나중에 만든 화면 |
| **심사** | `/balsatang/admin/review.html` | 새로 수집한 사료를 발행 전에 검토 |

`foods.html` 은 원래 없던 페이지다. "한 번 발행하면 손댈 방법이 없다" 는 문제를
메우려고 새 주소로 만들었고, 그때부터 `/balsatang/admin/` 을 편의상 "예전 어드민"
이라고 불렀다. 그 말이 화면에도 남아 혼란을 키웠다. 이 문서에서는
**어드민** / **사료 관리** / **심사** 로 부른다.

---

## 지금 실제로 어떻게 도는가

원하는 흐름은 이것이다.

```
크롤링 → 심사에서 승인 → 사료 관리에서 가격·링크 → 등록 → 프론트에 노출 → 수정은 사료 관리에서만
```

지금 상태를 같은 자리에 놓으면 이렇다.

| 단계 | 지금 | 사람 손이 필요한가 |
|---|---|---|
| ① 사료 수집 | 수집 에이전트와 스크립트가 있다 | **자동으로 돌지 않는다.** 실행을 시켜야 한다 |
| ② 게이트 검증 | `npm run gate1 / gate3` · CI 에서도 돈다 | 자동 |
| ③ 심사 화면에 올림 | 매일 오전 9시 · 스테이징이 바뀌면 Actions 가 만든다 | 자동 |
| ④ 승인 | 화면에서 고르고 **GitHub 에 발행** | 자동 (버튼 하나) |
| ⑤ 발행(= data.js 병합) | 심사 화면이 그 자리에서 커밋한다 | 자동 |
| ⑥ 가격·구매 링크 | 사료 관리에서 넣는다 | 사람이 넣는다 (파트너스 링크는 지어낼 수 없다) |
| ⑦ 프론트 노출 | 커밋되면 CI → 배포 → 몇 분 뒤 자동 | 자동 |
| ⑧ 수정 | 사료 관리에서 고치고 커밋 | 사람이 고친다 (그게 목적) |

**남은 곳은 ① 하나다.** ③④⑤ 는 이어졌다 — 심사 목록은 매일 자동으로 갱신되고,
승인을 누르면 그 자리에서 `data.js` 에 병합해 커밋한다. ⑥⑦⑧ 은 이미 원하는 대로 돈다.

### 남은 하나

- **① (수집)** — 사료 이름·성분표를 어디서 가져올지에 따라 다르다. 쿠팡은 봇 차단이
  강해 크롤링이 막혀 있고, 지금은 다나와와 공공데이터를 쓴다. 여기는 자동화해도
  **사람이 결과를 봐야 한다** — 잘못 긁힌 성분표가 그대로 발행되면 안 된다.

## 화면별 사용법

### 사료 관리 (`/balsatang/admin/foods.html`)

**발행된 사료를 고치는 곳.** 여기서 고치면 GitHub 에 커밋되고 몇 분 뒤 사이트에 반영된다.

1. 처음 한 번 **토큰**을 넣는다 (아래 "토큰 만들기").
2. 목록에서 사료를 누르면 오른쪽에 편집 패널이 열린다.
3. 고칠 수 있는 것:
   - 브랜드 · 제품명 · 제형 · 원산지 · 처방식 여부 · 연령 · 체형
   - 썸네일 URL
   - 대표 가격 · 용량 · 판매처 · **쿠팡 파트너스 구매 링크**
   - 판매처별 가격 행 (상세 화면의 최저가 비교)
   - **보장성분표** (조단백·조지방·조섬유·수분·조회분·생육 함량)
   - **원료** (표기 순서 그대로, 한 줄에 하나)
   - **소비자 요약 카드** — 자동 생성하거나 템플릿에서 고른다
   - **맞춤 태그** — 고르면 문장이 채워지고 그 자리에서 고친다
4. 고친 칸은 노랗게 되고 아래에 `원래: …` 가 붙는다.
5. 아래 바에서 **GitHub 에 커밋**.

**별점과 총점은 직접 못 고친다.** 원료나 성분표를 고치면 루브릭이 다시 계산한 값을
보여주고(`원료 5 → 3`), **"다시 계산" 을 눌러야** 반영된다. 안 누르면 원래 점수가 남는다.
점수를 사람이 직접 입력하는 경로는 없다 — 그러면 점수의 근거가 사라진다.

**필터**로 할 일을 찾는다: 썸네일 없음 / 구매링크 없음 / 가격 없음 / 분석 준비 중.

### 심사 (`/balsatang/admin/review.html`)

**새로 수집한 사료를 발행 전에 보는 곳.** 대기 건이 없으면 빈 화면이 정상이다.

1. 카드를 눌러 펼친다.
2. 게이트가 잡은 문제와, 심사 AI 가 따로 조사해 대조한 결과가 보인다.
3. 값이 틀렸으면 **고치기**에서 바꾼다. 별점은 루브릭이 다시 계산한다.
4. 구매 링크를 넣는다 (쿠팡이 아니면 경고가 뜬다).
5. **발행 / 반려**를 고르고 아래 **GitHub 에 발행**.
   승인한 건이 `data.js` 에 병합되고, 스테이징에서 빠지고, 반려한 건은 기록으로 남는다.
   전부 한 커밋으로 올라간다. 몇 분 뒤 사이트에 반영된다.

게이트를 통과하지 못한 건은 발행 버튼이 눌리지 않는다. 승인 목록에 넣어도 발행되지 않는다.
심사 화면도 **토큰**이 필요하다(사료 관리와 같은 토큰).
'명령만 복사'는 예전 방식이라 터미널에서 처리할 때만 쓴다.

### 어드민 (`/balsatang/admin/`)

**성분 사전 · 콘텐츠 · 맞춤찾기 태그 · 리콜 · 리뷰.**

이 화면의 데이터는 **처음 열었을 때 브라우저에 복사해 둔 것**이라, 사료 관리에서
커밋한 내용이 자동으로 보이지 않는다. 사료 관리에서 뭔가 고쳤다면 여기 상단의
**최신 데이터 불러오기**를 눌러야 맞춰진다.

**이 화면의 사료 편집은 쓰지 않는다.** 만들 때의 데이터 형태가 지금과 달라서,
내보내면 `FOODS_ALL` 선언과 구매 링크가 통째로 빠진다. 그래서 내보내기를 막아뒀고
위저드에도 경고를 붙였다. 사료는 **사료 관리**에서만 고친다.

## 토큰 만들기

https://github.com/settings/personal-access-tokens/new

- Token name: 아무거나 (`balsatang-admin`)
- Expiration: 90 days
- Repository access: **Only select repositories** → `butblank-oss/gsso_scat`
- Permissions → Repository permissions → **Contents: Read and write** (이거 하나만)

만든 토큰을 사료 관리 화면 오른쪽 위 **토큰** 버튼에 붙여넣는다.
토큰은 그 브라우저에만 저장되고 저장소에는 들어가지 않는다.
어드민 주소는 공개돼 있으므로 권한을 저장소 하나 · Contents 로만 좁히고 만료를 짧게 둔다.

## 무엇을 내려받으라는 말이었나

예전에는 어드민이 파일(`data.js`)을 내려받게 하고, 그 파일을 저장소에 직접 올려야
반영됐다. **지금은 그 경로를 쓰지 않는다** — 사료 관리가 GitHub 에 바로 커밋한다.
`articles.js`(콘텐츠)만 아직 내려받는 방식이 남아 있다.
