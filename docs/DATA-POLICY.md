# 발사탕 데이터 정책

사료 정보는 제조사 매출에 직접 영향을 준다. 잘못된 정보는 명예훼손이 될 수 있다.
이 문서는 어떤 정보를 어떤 근거로 실을 수 있는지를 정한다. 예외는 없다.

---

## 1. 발행 원칙

**근거 없는 정보는 싣지 않는다.** 확인되지 않으면 비워두거나 폐기한다.
추측해서 채우지 않는다. 41종이 39종이 되는 것이, 1종이 틀린 것보다 낫다.

수집·심사는 자동으로 하되, **발행은 사람이 한다.** 자동 발행 경로는 두지 않는다.

---

## 2. 상태 (status)

| 값 | 뜻 | 사이트 노출 |
|---|---|---|
| `draft` | 수집됨, 심사 전 | ❌ |
| `review` | 게이트 통과, 발행 대기 | ❌ |
| `published` | 사람이 발행 승인 | ✅ |
| `rejected` | 반려 | ❌ |
| `stale` | 재검증에서 불일치, 자동 내림 | ❌ |

`published` 외에는 사용자에게 절대 노출하지 않는다.

## 3. 출처

### 3.1 등급

| 등급 | 출처 | 성분 근거로 | 가격 근거로 |
|---|---|---|---|
| A | 제조사 공식 사이트 | ✅ | ❌ |
| A | 국내 공식 수입사 | ✅ | ❌ |
| B | **쿠팡 상품 상세페이지** | 보조만 | ✅ |
| C | 블로그·카페·리뷰·커뮤니티 | ❌ | ❌ |
| C | AI 기억 / 검색 요약문 | ❌ | ❌ |

C등급은 근거로 쓸 수 없다. 참고로도 기록하지 않는다.

### 3.2 필수 조건

- **성분**: A등급 1곳 이상. A가 없으면 B등급 2곳 이상이 서로 일치해야 한다.
  국내 수입사·국내 판매처 표기를 우선하되, 해외 공식 표기만 확보되어도 등록한다.
  대신 어느 쪽인지 반드시 표시한다 (아래 3.5).
- **가격**: **쿠팡만 인정한다.** `coupang.com` 도메인의 상품 페이지여야 한다.
  다나와·네이버·11번가 등 가격비교 사이트는 쿠팡 상품을 찾는 도구로만 쓰고,
  출처로 기록하지 않는다. 확인 날짜를 반드시 기록한다.

### 3.5 성분 출처 국가 표시

성분표는 국내 유통품과 해외 원산지 제품의 배합이 다를 수 있다.
등록은 하되 **어느 쪽 기준인지 사용자에게 그대로 알린다.**

| `specOrigin` | 조건 | 사용자에게 |
|---|---|---|
| `domestic` | A등급 출처에 국내(`.kr` 또는 쿠팡)가 1곳 이상 | 🟢 **국내 기준** 배지 |
| `overseas` | A등급 출처가 전부 해외 | 🟡 **해외 성분표 기준** 배지 + 안내문 |

해외 기준일 때 상세 화면에 다음을 띄운다.

> 이 사료의 성분 정보는 **제조사 해외 공식 사이트** 기준이에요.
> 국내 유통 제품은 배합이 다를 수 있으니, 정확한 성분은 **제품 봉투 표기**를 확인해 주세요.

게이트 1이 `specOrigin` 표기와 실제 출처가 일치하는지 검사한다.
표기를 속이면 탈락한다.

### 3.6 가격 미확보 — 임시저장

쿠팡 상품 URL 을 못 구했다고 조사 결과를 버리지 않는다.
`pricePending: true` 로 표시해 스테이징에 남긴다.

| | 가격 확보 | 가격 대기 |
|---|---|---|
| `price` | 있음 | **없음** |
| `ratings.value` | 1~5 | **null** |
| `score` | 계산됨 | **null** |
| 게이트 1 | 통과 / 탈락 | **보류(pending)** |
| 발행 | 가능 | **불가** |

가성비 점수가 빠지면 총점을 낼 수 없으므로 사용자에게 노출할 수 없다.
나머지 3개 항목(원료·탄수화물·첨가물)은 그대로 채점해 두므로,
가격만 들어오면 바로 발행된다.

### 3.4-1 구매 링크 (쿠팡 파트너스)

가격 **근거**와 사용자가 여는 **구매 링크**는 다른 것이다.

| 필드 | 무엇 | 형식 |
|---|---|---|
| `sources[].url` (role: retail) | 가격을 확인한 곳. 게이트가 검사한다 | `coupang.com/vp/products/{id}` |
| `price.buyUrl` | 구매 버튼이 여는 곳 | 쿠팡 도메인이면 된다 (`link.coupang.com/a/…`) |

**수수료는 파트너스 링크로 들어온 구매에만 붙는다.** 정식 상품 URL 로는 한 푼도 들어오지 않는다.
그래서 `buyUrl` 이 비어 있으면 게이트 1이 경고한다(탈락은 아니다).

**파트너스 링크는 사람만 만들 수 있다.** API 권한이 나오기 전까지는 상품마다 직접 만들어야 한다.
따라서 사료를 심사에 올릴 때는 **반드시 사람에게 링크를 요청한다.** 링크 없이 발행하지 않는다.

```bash
node scripts/buy-links.mjs              # 링크 없는 사료와 열어야 할 상품 페이지 목록
node scripts/buy-links.mjs --set l.json # 받은 링크를 검증하고 data.js 에 반영
```

`--set` 은 단축링크를 실제로 열어(302 Location) 어느 상품으로 가는지 확인하고,
등록된 출처와 다른 상품이면 경고한다. 다른 제품으로 가는 링크를 모르고 싣지 않기 위해서다.

심사 화면에서는 카드 안 **구매 링크** 칸에 붙여넣으면 발행 명령에 함께 실린다.

### 3.4 가격 기준 용량

같은 사료라도 용량에 따라 kg당 가격이 2배 가까이 차이난다.
**판매 중인 용량 중 가장 작은 것**을 기준으로 한다.

```
인스팅트 BE 내추럴 연어   1kg 21,660원 → kg당 21,660원  ← 이걸 쓴다
                        10.8kg 135,130원 → kg당 12,512원
```

작은 용량은 처음 사보는 사람이 실제로 지불하는 가격이고, 대용량 할인은
브랜드마다 편차가 커서 비교 기준으로 부적절하다.

`price.wgOptions` 에 확인한 용량을 모두 적고, `price.wg` 는 그중 최솟값이어야 한다.
게이트 1이 이를 검사한다.
- 모든 출처는 **URL 원문**과 **확인 시각**, 그리고 **근거 문장 원문 인용**을 남긴다.
  인용 없이 URL만 있는 항목은 게이트 1에서 자동 탈락한다.

### 3.3 유효기간

| 항목 | 유효기간 | 지나면 |
|---|---|---|
| 가격 | 30일 | `stale` 표시, 재수집 대상 |
| 성분 | 365일 | 재검증 대상 |

## 3.7 상세 화면은 자동으로 만든다

판정 카드·영양 프로파일·원료 분석·적합도는 **사람도 AI도 쓰지 않는다.**
`scripts/lib/derive.mjs` 가 규칙으로 만든다. 점수를 루브릭이 매기는 것과 같은 이유다 —
지어낸 문장은 검증할 수 없다.

| 사람·AI 가 옮기는 것 | 코드가 만드는 것 |
|---|---|
| `ga` — 보장성분표 숫자 | 영양 프로파일 |
| `ingredients` — 원재료명, 표기 순서대로 | 원료 분석·안전도 분포 |
| | 판정 카드 (좋음/주의/위험) |
| | 기능성 원료 |
| | 이런 아이에게 어떨까요 |

둘 다 **필수**다. 없으면 게이트 1에서 탈락한다 — 상세 화면이 빈 채로 나가기 때문이다.

원료 사전(`scripts/lib/ingredients.mjs`)에 없는 원료는 `unknown` 으로 남긴다.
모르는 것을 안전하다고 하지 않는다.

## 4. 점수

**AI는 점수를 매기지 않는다.** 사실(facts)만 출처와 함께 뽑고,
`ratings` 는 아래 루브릭이, `score` 는 공식이 계산한다.
게이트 1이 제출된 `ratings` 를 루브릭으로 다시 계산해 대조하므로, 임의 채점은 통과하지 못한다.

### 4.1 항목별 루브릭

| 항목 | 기준 | 기존 41종 재현율 |
|---|---|---|
| **원료** | 조단백 32%↑=5 · 25%↑=4 · 16%↑=3 · 미만=2<br>단, 1번 원료가 곡물이면 최대 3점 | 71% (±1 이내 100%) |
| **탄수화물** | 건물기준 탄수 25%↓=5 · 35%↓=4 · 44%↓=3 · 56%↓=2 · 초과=1 | 95% |
| **첨가물** | 주의 성분 0개=5 · 1~2개=4 · 3~4개=3 · 5개↑=2<br>단, 위험 성분이 있으면 최대 3점 | 85% |
| **가성비** | kg당 1만원↓=5 · 1.6만↓=4 · 3.2만↓=3 · 4.5만↓=2 · 초과=1 | 90% |

전체 164개 판정 중 140개(85%)가 기존 채점과 정확히 일치한다.
구현은 `scripts/lib/rubric.mjs`.

### 4.2 성분 분류

**주의 성분** — 천연 향미제, 효모 추출물, 곡물 충전재(옥수수·밀·대두),
출처 불명 육분, 출처 불명 동물성 유지, 정제 소금, 카라기난, 셀룰로스

**위험 성분** — BHA, BHT, 에톡시퀸, 프로필갈레이트, 인공 착색료,
아질산나트륨, 프로필렌글리콜

### 4.3 종합 점수

```
score = 2 × (0.45·원료 + 0.28·첨가물 + 0.20·탄수화물 + 0.07·가성비)
```

소수점 1자리, 2.0 ~ 10.0. 기존 41종에 평균 오차 0.20으로 부합한다(39/41이 ±0.5 이내).

**기존 41종의 점수는 소급 변경하지 않는다.** 재검증 시점에 갱신한다.

## 5. 표현

사료사 매출에 영향을 주는 서비스이므로, 단정적·부정적 단어를 쓰지 않는다.

| 쓰지 않는다 | 대신 쓴다 |
|---|---|
| 나쁜 사료, 최악, 위험 | 점수, 등급 |
| 발암, 독성, 유해 | 해당 성분 표기 + 출처 |
| 먹이지 마세요 | 참고하세요 |

성분에 대한 평가는 **사실 서술 + 출처**로만 한다.
"이 사료는 X 성분이 있어 위험합니다"가 아니라
"전성분표에 X가 표기되어 있습니다(출처)"로 쓴다.

## 6. 리콜

리콜은 오보의 피해가 가장 크다. 별도 기준을 적용한다.

### 6.1 인정 출처 (이 외 불가)

- 식품의약품안전처
- 농림축산식품부 / 농림축산검역본부
- 해당 제조사·수입사 **공식 발표**
- 해외: FDA, 각국 정부기관

언론 보도는 **단독 근거로 쓸 수 없다.** 보도에 인용된 원 공고를 찾아야 한다.

### 6.2 필수 조건

- 공고 **원문 URL**이 있어야 한다
- 그 페이지 본문에 **해당 브랜드명이 실제로 포함**되어야 한다 (기계 검증)
- 대상 제품명·로트번호·회수 사유·공고일을 그대로 옮긴다

### 6.3 발송

- **자동 발송하지 않는다.** 사람이 확인하고 발행한다.
- 알림 본문에 **공고 원문 링크를 반드시 포함**한다
- 발사탕의 해석을 덧붙이지 않는다. 공고 내용만 전달한다

- 처리 이력을 남긴다

## 8. 자동화 경계

| 자동으로 한다 | 사람이 한다 |
|---|---|
| 사료 후보 수집 | **발행 승인** |
| 출처 확보·인용 | **값 수정** |
| 게이트 1·2·3 검증 | **리콜 발행** |
| 별점·총점 계산 | 이의제기 판단 |
| 재검증·`stale` 강등 | 정책 변경 |
| 반려·폐기 | |

자동화가 사람에게 올리는 것은 **게이트를 전부 통과한 건**뿐이다.
탈락한 건은 사람을 부르지 않고 `data/rejected/` 에 기록만 남긴다.

### 8.1 사람이 값을 고칠 때

심사 화면(`balsatang/admin/review.html`)의 **고치기**에서 아래 값을 직접 바꿀 수 있다.

`facts.protein` · `facts.dmCarb` · `facts.firstIngrCat` · `facts.cautionN` · `facts.dangerN` · `price.p` · `price.wg`

**별점과 총점은 고칠 수 없다.** 고친 사실값으로 루브릭(§4)이 다시 계산한다.
사람이든 AI든 점수를 직접 입력하는 경로는 없다.

수정한 값은 '발행 명령 복사'에 `edits` 블록으로 함께 실린다.
`node scripts/apply-edits.mjs` 가 그것을 스테이징에 반영하면서:

- `ratings` 와 `score` 를 다시 계산한다
- `price.pKg` 를 다시 계산한다
- 바뀐 값·사유·이전 값을 `audit.humanEdits` 에 남긴다
- **`audit.verdict` 를 무효화한다** — 값이 바뀌었으니 심사 AI 대조 결과는 더 이상 그 값에 대한 것이 아니다

마지막 항목 때문에 고친 건은 게이트를 다시 통과해도 자동으로 발행 후보가 되지 않는다.
대조를 다시 붙이거나, 남긴 사유를 근거로 사람이 다시 승인해야 한다.

수정 사유는 비워도 되지만, **비워두면 왜 바꿨는지가 기록에 남지 않는다.**
근거가 된 문장이나 링크를 적는 것을 원칙으로 한다.

### 8.2 발행된 뒤에 값을 고칠 때

8.1 은 **아직 발행하지 않은 건**에 대한 이야기다.
이미 발행된 사료를 고치는 자리는 **사료 관리 화면**(`balsatang/admin/foods.html`)이다.
이 화면은 `balsatang/data.js` 를 GitHub Contents API 로 직접 커밋한다.
커밋이 올라가면 CI 가 `verify-data.mjs` 를 포함한 검사를 돌리고, 통과하면 Pages 가 배포한다.

**고칠 수 있는 값** — 사람이 눈으로 확인해서 판단하는 값만 연다.

브랜드 · 브랜드 슬러그 · 제품명 · 제형 · 원산지 · 처방식 여부 · 연령 · 체형 · 썸네일 URL ·
대표 가격(`price.p` / `price.wg` / `price.shop` / `price.buyUrl`) · 판매처별 가격 행(`DETAIL[id].prices`)

**고칠 수 없는 값**

- `ratings` · `score` — 루브릭이 계산한다. 가격을 고쳐서 가성비 구간이 달라지면
  "이 가격이면 N점" 을 보여주고, 사람이 **별점·총점 다시 계산**을 눌러야 반영한다.
  누르지 않으면 원래 점수를 그대로 둔다. 예전 41종은 원본 앱의 점수를 물려받았기 때문에,
  손대지 않은 사료의 점수까지 일괄로 움직이면 안 된다.
- 원료(`ingr`) · 영양 수치(`nutrient`) — 출처와 증거가 함께 바뀌어야 하는 값이라
  심사 화면(스테이징)의 몫이다. 이 화면에서는 읽기 전용으로만 보인다.

**커밋 전 검사** — 브랜드/제품명 공백, 연령·체형 미선택, 가격·용량이 숫자가 아닌 경우,
가격만 있고 용량이 없는 경우, kg당 가격이 상식 범위 밖인 경우,
구매 링크가 쿠팡 도메인이 아닌 경우를 막는다.

**동시 수정** — 파일의 `sha` 를 같이 보낸다. 그 사이 저장소가 바뀌었으면 409 로 막히고
"다른 곳에서 먼저 바뀌었습니다" 가 뜬다. 모르고 덮어쓰는 것보다 낫다.

**토큰** — fine-grained personal access token 을 쓴다.
Repository access 는 `butblank-oss/gsso_scat` 하나, Permissions 는 Contents = Read and write,
만료는 되도록 짧게. 토큰은 그 브라우저의 `localStorage` 에만 두고 **저장소에 절대 넣지 않는다.**
어드민 페이지는 공개 도메인에 있으므로 이 페이지에 XSS 가 생기면 토큰이 새어나갈 수 있다.
권한을 저장소 하나·Contents 로만 좁히고 만료를 짧게 두는 것이 그 전제다.
조직 계정 토큰이나 classic 토큰은 쓰지 않는다.
