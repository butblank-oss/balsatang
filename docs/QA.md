# 발사탕 QA — 테스트 케이스와 발견 사항

화면이 넷이고 서로 같은 데이터를 본다. 한쪽에서 고친 게 다른 쪽에서 사라지거나,
눌러도 아무 일이 없거나, 글자가 안 보이는 일이 실제로 있었다.
그래서 사람이 매번 눈으로 훑는 대신 기계가 돌 수 있는 만큼 돌게 했다.

```
npm run qa          # 네 화면 전부
node scripts/qa/front.mjs    # 하나만
```

브라우저가 없으면 한 번만 `npx playwright install chromium`.
이미 깔린 크로미움이 있으면 `QA_CHROME=/경로/chrome npm run qa`.
화면 캡처는 `.qa-out/` 에 쌓이고 저장소에는 올리지 않는다.

---

## 무엇을 자동으로 잡는가

사람이 "어색하다" 고 느끼는 것 중 기계가 판정할 수 있는 것만 골랐다.

| 점검기 | 잡는 것 | 왜 |
|---|---|---|
| `deadClicks` | 눌러도 화면·주소·DOM·토스트 어느 것도 안 바뀌는 버튼 | 콘텐츠 카드 50개가 그랬다 |
| `lowContrast` | WCAG AA 미달 글자 (본문 4.5:1, 큰 글자 3:1) | 보라 배경에 회색 글자가 실제로 있었다 |
| `overflowX` | 본문이 화면 밖으로 삐져나감 | 좁은 화면에서 가로 스크롤이 생기는 것 |
| `hiddenUnderBar` | 고정 바에 가려 못 읽는 본문 | 하단 탭바에 글이 깔리던 것 |
| `brokenImages` | 주소는 있는데 안 불러와지는 이미지 | 죽은 썸네일 경로 |
| `watch` | JS 오류 · 404 · 콘솔 에러 | 조용히 나는 오류 |

**대비 계산 주의** — 반투명 배경은 아래 색과 합성해야 실제 보이는 색이 나온다.
합성하지 않으면 보라 위의 흰 반투명 배지가 "흰 배경에 흰 글자" 로 잘못 잡힌다.
그림·그라데이션 배경 위의 글자는 색으로 판정할 수 없어 검사에서 뺀다.

## 정책이 필요한 지점

기계가 판정할 수 없어 사람이 정해야 하는 것들. **아직 정하지 않았다.**

### 1. 쿠팡이 아닌 판매처를 남길 것인가

정책은 "판매처는 쿠팡만 인정"(DATA-POLICY 3.4)인데, 기존 41종에 `brand_official` 가격이
남아 있고 게이트는 그걸 막지 않았다. 지금은 **경고만** 붙게 했다(`W_SHOP_NOT_COUPANG`).

- (가) 경고 유지 — 기존 데이터를 살리되 새 건은 사람이 본다
- (나) 탈락으로 격상 — 정책과 코드가 같아지지만 기존 41종을 손봐야 한다
- (다) 정책을 고쳐 공식몰을 인정 — 대신 그 가격엔 수수료가 안 붙는다는 걸 화면에 적어야 한다

### 2. 예전 어드민의 사료 편집을 어떻게 할 것인가

지금은 **두 곳에서 사료를 고칠 수 있는데 한 곳만 실제로 반영된다.**
예전 어드민의 편집은 브라우저에만 남고, 내보내기는 막아뒀다(구매 링크를 버리므로).
즉 그 화면의 사료 편집 기능은 지금 **아무 데도 도달하지 않는다.**

- (가) 예전 어드민의 사료 편집을 읽기 전용으로 바꾸고 사료 관리로만 보낸다 — 가장 헷갈리지 않는다
- (나) 사료 관리 화면에 원료·영양·판정 편집을 옮겨 심고, 예전 어드민의 사료 부분을 걷어낸다 — 목표 상태
- (다) 예전 어드민을 지금 형태에 맞게 고쳐 GitHub 커밋을 붙인다 — 편집기가 둘로 남아 계속 어긋난다

(나)가 목표고 (가)는 그 사이의 임시 조치다.

### 3. 요청 접수 창구

'이 사료 분석 요청하기' 는 지금 "접수 창구를 준비 중이에요" 만 띄운다.
받을 곳이 없기 때문이다. 서버를 붙이기 전까지 무엇으로 받을지 정해야 한다
(구글 폼 / 이메일 / 아무것도 안 받고 버튼을 감추기).

### 4. 원료·영양 수치를 어드민에서 고칠 수 있게 할 것인가

지금은 못 고친다. 출처와 증거가 같이 바뀌어야 하는 값이라 심사 화면의 몫으로 뒀다.
발행된 사료의 성분표가 바뀌었을 때 어떻게 할지가 아직 없다 —
스테이징에 다시 올려 심사를 태울지, 어드민에서 출처를 같이 입력받을지.
